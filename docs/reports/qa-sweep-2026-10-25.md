## Findings

### 1. Sixteen reachable standard-library vulnerabilities in the public build — FIXED (toolchain)

v0.1.7-pre is built with go1.25.12. govulncheck finds 16 vulnerabilities whose
vulnerable symbols the agent actually reaches: through the loopback API server
(`net/http`, `crypto/tls`, `crypto/x509`, `encoding/asn1`) and through the
outbound feed, RDAP and VirusTotal clients (`net/url`, `net/http`). Five are
fixed only in the go1.26 line (among them x509 distrust of compromised
intermediates, GO-2026-6809, and an HTTP/2 HPACK encoder race, GO-2026-6617),
so no go1.25 patch clears them. All are fixable, so under the "zero fixable"
bar this blocks Gate 4.

Fixed in `7b4338d` by moving the toolchain to **go1.26.10**, the smallest
step that clears all of them. The language version stays 1.25.0. Note that
`govulncheck` itself had to be rebuilt with go1.26 to load the packages.

**The public binary still carries these until a new pre-release is cut.**

### 2. staticcheck + gitleaks — FIXED

- `proctable_windows.go`: the buffer-sizing `EnumServicesStatusEx` call
  assigned an error nothing read (SA4006). It is expected to fail with
  ERROR_MORE_DATA; now says so.
- `filewatch_test.go`: dead assignment in a loop (SA4006).
- `normalizeImagePath` / `deviceVolumeRe` reported unused on Linux because only
  the Windows ETW source calls them — which also meant zero coverage on the
  machine the suite runs on. Now tested.
- gitleaks `generic-api-key` in `namecache_test.go`: a fake kernel pointer used
  as an ETW file key. Recorded in `.gitleaksignore`.
- Also removed the zero-byte file named `=` from the repo root.

### 3. The story named whoever resolved the address, not who connected — FIXED

The headline sentence of every connection's story is built by `Narrate`, whose
subject was "the latest step in the chain that has a name". The chain also
holds the DNS lookup that produced the address — and the graph keeps the most
recent resolution of an address by **any** process, so on shared CDN addresses
that lookup is routinely another program's. Live network events carry no image
of their own, so the walk landed on the other program. For `updater.exe`
connecting to an address `browser.exe` had resolved:

> browser.exe was already running. It looked up cdn.test, connected to cdn.test (203.0.113.9:443).

Wrong program, and a lookup it never made. Same family as the two attribution
bugs fixed in July (recycled PIDs, recycled file handles). Fixed in `2086a8b`:
the subject comes only from the connection's own image, the `ProcStart` with
its PID, or the context built for that PID; "looked up" only when the
connecting process made the lookup. Regression test fails on the old code.
Narratives are frozen at record time, so rows already in a ledger keep their
old text.

### 4. Two places told the reader each story step caused the next — FIXED

The stored Mermaid diagram joined steps in Lamport order, and the dashboard's
story modal said each step "is an event that *caused* the next". Lamport order
is ordering, not causation: the cross-process lookup in Finding 3 sits among
the dialer's own ancestors. Mermaid arrows now come from the poset's edges
(`f37ec06`); the modal copy is corrected (`9ede441`).

### 5. "Test me" reported the beaconing rule broken on every press after the first — FIXED

Found by pressing the button more than once. On a fresh agent the self-test
passes; every later run reported `c2-beaconing` as not firing, and clearing the
drill alerts did not help. The beacon tracker latches per program+destination
after alerting (so a steady beacon is one alert, not one a minute), and the
drill reuses one reserved program and destination. A self-test that tells a
user a working detection is broken is the worst false result it can give.
Fixed in `370ec11`: the drill forgets its own flow first. Regression test runs
the self-test three times on one engine and fails at run 2 on the old code.
Verified live afterwards: 14/15 fired three times in a row with `--no-feeds`
(the feed rule correctly skipped), and **15/15** with feeds enabled (3/3 feeds
loaded, 7,607 addresses).

## Minor observations (not fixed)

- `normalizeImagePath` maps `HarddiskVolume3` to `C:` by assumption. Common,
  not universal; documented in the code.
- On first launch the tip modal appears over the dashboard, and redraws pause
  while any modal is open, so the table is blank behind it until dismissed.
  By design; noted because it briefly looks like an empty ledger.
- A Go binary built inside a `git worktree` stamps the enclosing repository's
  revision (Go only recognises a `.git` directory). Release builds must come
  from the main checkout; now in the README.
