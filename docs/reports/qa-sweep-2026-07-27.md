## Findings

### 1. Critical ransomware alerts shipped with no buttons, while telling the user to press one — FIXED

`respond.Suggest` had cases for `c2` and `persistence`. The rule packs ship
**four** areas. So all three ransomware rules (two of them `critical`) and the
credential-theft rule rendered with an empty action row, while their own
playbook text said:

> "Stop the program now using the button below, or hold the power button to
> shut down. Speed matters more than tidiness."

There was no button below. Six playbook steps across the packs promise a
button; four of those promises were broken.

This is the most serious finding in either sweep, because it fails in exactly
the moment the product exists for. It is also precisely the "confident
wrongness" failure mode the design doc warns about — the difference is that
here the tool was confidently wrong about *itself*.

Found by replaying `testdata/traces/ransomware.jsonl` against a local dev
deploy and asking `/api/actions?alert=1` what it offered. It answered `null`.
No unit test caught it because no test asserted the relationship between what a
playbook promises and what `Suggest` returns.

**Fixed** in `ab27b33`: both areas added, with three regression tests that fail
against the previous code — the button-exists invariant, the stop-before-
quarantine ordering, and float64 PID formatting (a PID round-tripped through
the ledger's JSON formats as `1.234568e+06` under `%v`, which `taskkill`
rejects — silently breaking the stop button on any long-uptime machine).

Verified end to end: the dashboard now renders "Stop invoice.exe now (cannot be
undone)" and "Quarantine this program" under the playbook that promises them.

### 2. Repo hygiene (issue #2) — FIXED

Three of the five findings in #2 had already been fixed incidentally since it
was filed (tracked Linux binary, tracked runtime log, `event.go` gofmt drift).
The remainder, closed in `bec2d4c`:

- `agent/dist/run-nitewatch.bat` was a byte-identical duplicate of
  `agent/scripts/run-nitewatch.bat`. Untracked; `dist/` now ignored — both of
  them, since two dist dirs exist in practice (`agent/dist/` from an in-tree
  build, `dist/` from `go build -o ../dist`).
- `CLAUDE.md` claimed a SvelteKit dashboard. It is a single embedded HTML file
  and has been since P1. Corrected, with the reason it has stayed that way. The
  plan docs are left alone — the P1 plan already records the substitution
  honestly ("embedded vanilla HTML (SvelteKit deferred to P2)"), and rewriting
  a completed plan would erase the record rather than fix it.
- `dashboard/` was an empty dir holding a `.gitkeep`, scaffolding for a
  SvelteKit app deferred through P1 and never built in P2, plus three
  `.gitignore` lines for a `node_modules` that has never existed. Removed.
- The launcher `.bat` was undocumented; removing its `dist/` copy would have
  orphaned it. The README now covers the cross-compile and states that the exe
  must ship beside it, because the launcher self-elevates and runs
  `nitewatch.exe` from its own directory.

### 3. `malicious.jsonl` is a misleading smoke-test fixture — NOT FIXED, noted

The trace named `malicious.jsonl` produces **zero alerts** under
`--no-recon`. This is correct behaviour, not a bug: the `c2-raw-ip-no-dns`
detector deliberately requires address-ownership data (`s.Recon.Org != ""`),
the guard added to stop it firing on every restart before the dataset loads.

But a fixture called "malicious" that is silent by default is a trap for the
next person smoke-testing, and it cost time in this sweep. Either it should
carry a note, or the smoke-test recipe should say which traces need `--recon`.
Left as-is for now; flagged so the next sweep does not rediscover it.

### 4. Signature verification is unavailable off Windows — known, restated

`platform.FileSigner` returns `(false, "")` on non-Windows, which means every
binary looks unsigned during replay testing. The stub documents this and the
direction is the safe one (rules that suppress on a trusted signature simply do
not suppress). Worth restating because it means **signature-dependent rules
cannot be meaningfully exercised on the dev box** — `c2-unsigned-first-contact`
and the unsigned half of `c2-raw-ip-no-dns` are only really testable on Windows.

## What this sweep did not cover

- Live ETW capture, elevation, toast notifications, browser-open.
- **Actual execution** of any remediation. `Suggest` is now verified to offer
  the right actions; `respond.Executor` running `taskkill` / `netsh` / `icacls`
  for real, and the undo path, remain untested outside Windows.
- The false-positive rate over a long real session — still the single most
  important unmeasured number in the product, and unchanged from the last
  sweep. Nothing here substitutes for a week of soak on a real machine.
